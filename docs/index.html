Everything you need to talk to Firestore over REST.

From a single decode to a full batch write — the library covers the REST surface area you actually use.

Unified async API

Configure once, then db.decode(User.self, from: "users/user1"). Handles URL building, auth, networking, and decoding in one call.

Local parsing only

FirestoreDocumentParser parses JSON you already fetched — no networking, perfect for tests and cached payloads.

JSONDecoder extension

Normalize Firestore JSON to flat JSON, then decode with a standard JSONDecoder. Bring your own date/data strategies.

swift-dependencies

Protocol-based FirestoreClient with live and mock implementations, registered as @Dependency for clean DI and testing.

Property wrappers

@DocumentID, @ServerTimestamp, @ExplicitNull — the same API as the Firebase iOS SDK.

Encoding

Encode Swift models back to the Firestore REST wire format — full documents or fields-only for merging.

Write operations

commit, batchWrite, batchGet, and a FirestoreBatch builder for create / update / delete.

Service account auth

Mint and auto-refresh OAuth2 tokens from a service account JSON key. Custom providers supported.

Four API styles. Pick what fits.

The same library, four ergonomics — from a zero-config parser to full dependency injection.

01

FirestoreDocument

Unified async API. Configure once, then read and write in one call.

let db = FirestoreDocument(config: config)
let user = try await db.decode(
  User.self, from: "users/user1"
)
02

FirestoreDocumentParser

Local parsing only — no networking. Great for tests and cached data.

let parser = FirestoreDocumentParser()
let user = try parser.decode(
  User.self, from: jsonData
)
03

JSONDecoder.firestoreDecode

Normalizer plus a standard JSONDecoder. Bring your own strategies.

let decoder = JSONDecoder()
decoder.dateDecodingStrategy = .iso8601
let user = try decoder.firestoreDecode(
  User.self, from: data
)

@Dependency(\.firestoreClient)

swift-dependencies integration for DI and testing with a mock client.

@Dependency(\.firestoreClient) var client
let users = try await client.decode(
  [User].self, from: "users"

Decode, write, batch — in a few lines.

Property wrappers work out of the box, just like the Firebase iOS SDK.

01 — Decode

Decode a document in one call.

Property wrappers work out of the box — @DocumentID, @ServerTimestamp, @ExplicitNull — the same API as the Firebase iOS SDK. Configure once, then read a collection or a single document.

Decode 
import FirestoreRestDocuments

struct User: Decodable {
  @DocumentID var id: String?
  let name: String
  let age: Int
  @ServerTimestamp var createdAt: Date?
}

let db = FirestoreDocument(config: config)
let user = try await db.decode(User.self, from: "users/user1")
let users = try await db.decode([User].self, from: "users")
02 — Write

Create, update, delete — with field masks.

Send commit or batchWrite with preconditions. create fails if the document exists; update upserts when no mask is given.

Write 
let db = FirestoreDocument(config: config)

// Create (fails if it already exists)
let write = try FirestoreWrite.create(newUser, at: "users/new-user")
_ = try await db.commit(writes: [write])

// Update with a field mask
let update = try FirestoreWrite.update(user, at: "users/abc123", updateMask: ["email"])
_ = try await db.commit(writes: [update])

// Delete
_ = try await db.commit(writes: [.delete(at: "users/abc123")])
03 — Batch

Group writes into one atomic commit.

Build a FirestoreBatch of creates, updates, and deletes — or use batchWrite for per-write status reporting and labels.

Batch 
var batch = FirestoreBatch()
try batch.create(newUser, at: "users/new")
try batch.update(user, at: "users/existing", updateMask: ["email"])
batch.delete(at: "users/old")
let result = try await batch.commit(using: db)

// Or non-transactional:
let response = try await db.batchWrite(writes: writes, labels: ["env": "prod"])
04 — Wrappers

Property wrappers, just like Firebase.

@DocumentID populates from the document name, @ServerTimestamp decodes as Date, and @ExplicitNull keeps nil fields as explicit nulls.

Wrappers 
struct Item: Codable {
  let name: String
  @ServerTimestamp var createdAt: Date?
  @ExplicitNull var nickname: String?
}

struct User: Decodable {
  @DocumentID var id: String?
  let name: String
  let email: String
}

Five layers, one pipeline.

Each layer is optional — use the one that fits your app.

1

Normalizer

Unwraps {"stringValue":"Alice"} → "Alice", then hands flat JSON to JSONDecoder.

2

Custom Decoder / Encoder

Implements Swift's Decoder/Encoder directly on the FirestoreValue tree. Handles Date, Data, GeoPoint and wrappers natively.

3

Unified API

FirestoreDocument combines URL construction, auth, async networking, and decoding into one call.

4

Dependencies

Protocol-based FirestoreClient with live and mock implementations, registered as @Dependency values.

5

CLI + MCP

frd wraps the unified API; frd-mcp exposes read-only tools over stdio.

A CLI for your terminal and scripts.

frd brings the same REST operations to the shell — read, write, delete, batch, and list, with environment-based credentials.

  • frd get users/alice — fetch one document
  • frd list users --all — list a collection
  • frd set users/alice --data '{"name":"Alice"}'
  • frd delete users/alice users/bob
  • frd batch-write --file ops.json

Read-only MCP server out of the box.

frd-mcp exposes Firestore operations as MCP tools over stdio — plug it into Claude Desktop, Claude Code, or Cursor and ask questions in natural language.

firestore_get_document firestore_list_documents firestore_list_collections

Credentials come from the environment, never from tool arguments. Writes are intentionally excluded.
